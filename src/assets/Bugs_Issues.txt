2.  Unable to Delete Added Attendance Record
Title: Unable to Delete Added Attendance Record
Bug ID: 002
Module: Attendance
Page: Team Attendance
Bug Summary: Unable to delete an attendance record after it has been added.
Description: After adding a new attendance record in the Team Attendance page, clicking the Delete button does not remove the record. Instead, an error message is displayed.
Steps to Reproduce:
1. Go to Attendance → Team Attendance.
2. Click Add Attendance.
3. Add and save a new attendance record.
4. Click the Delete icon for the added record.
5. Confirm the deletion.
Expected Result: The attendance record should be deleted successfully, and a confirmation message should be displayed.
Actual Result: The attendance record is not deleted. The system displays the error message: "new row violates row-level security policy for table 'attendance'"

3.Title: Future Dates Can Be Selected in Team Attendance Date Filter
Bug ID: 003
Module: Attendance
Page: Team Attendance
Bug Summary: The From and To date fields are automatically populated with the current date, but users can still select future dates.
Description: On the Team Attendance page, the From and To date fields default to the current date. However, the date picker allows users to select future dates, even though attendance records for future dates cannot exist.
Steps to Reproduce:
1. Navigate to Attendance → Team Attendance.
2. Observe that the From and To date fields are set to the current date.
3. Open either date picker.
4. Select a future date.
Expected Result: Future dates should be disabled or restricted. Users should only be able to select the current date or past dates.
Actual Result: The system allows users to select future dates in the From and To date fields.




  
  

4. Attendance Status Can Be Saved with Invalid Working Hours
Bug ID: 004
Module: Attendance
Page: Add Attendance
Bug Summary: The system allows users to select and save an attendance status that does not match the employee's working hours.
Description: While adding attendance, the system does not validate the selected Status against the entered Check-In and Check-Out times. Even when the total working hours are approximately 9 hours (full-day), users can select statuses such as Late or Absent, and the record is saved successfully with the selected status.
Steps to Reproduce:
1. Navigate to Attendance → Team Attendance → Add Attendance.
2. Select an employee.
3. Enter Check-In and Check-Out times totaling around 9 working hours.
4. Select the status as Late or Absent.
5. Save the attendance record.
Expected Result: The system should validate the attendance status based on the working hours and business rules. Invalid status selections should either be restricted or display a validation message.
Actual Result: The system allows the attendance record to be saved with an incorrect status that does not match the entered working hours.

5.Duplicate Payroll Generation Displays Raw Database Error
Title: Duplicate Payroll Generation Displays Raw Database Error
Bug ID: BUG_001
Module: Payroll
Page: Run Payroll
Bug Summary: Generating payroll for an already processed period displays a raw database error instead of a user-friendly message.
Description: When the user generates payroll for a month that has already been processed, the application displays a PostgreSQL duplicate-key error instead of handling the validation gracefully.
Steps to Reproduce:
1. Go to Payroll → Team Payroll → Run Payroll.
2. Select Month: August and Year: 2026.
3. Click Generate Payroll for a payroll period that has already been generated.
Expected Result: The system should prevent duplicate payroll generation and display a friendly message such as "Payroll for the selected period has already been generated."
Actual Result: A red error message is displayed: "duplicate key value violates unique constraint 'payroll_items_unique_per_employee'".
Severity: Critical
Priority: P1
Category: Missing Validation / Error Handling
Suggested Fix: Handle duplicate payroll generation on the server side and display a user-friendly validation message instead of the database error.
